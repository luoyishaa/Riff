# 本地项目模式

本地项目模式把一个空间绑定到运行 `@collab/server` 的那台电脑上的目录。空间仍然是成员、权限、评论、建议和 Agent 的协作边界；目录只提供文档文件的来源。

在“新建项目”时，或由 owner 在项目设置（侧栏的齿轮按钮）中，选择本地文件夹或填写服务端目录路径，连接后立即完成绑定和首次扫描；项目设置同时列出每个文件的同步状态。后续双向协调通过项目侧栏的“同步”按钮触发。

## 两种绑定方式

### 服务端目录绑定

请求 `POST /api/workspaces/:id/local-project`，请求体为：

```json
{ "path": "D:/Projects/my-docs" }
```

`path` 必须是服务端进程可以读取的绝对目录。服务端会递归扫描 `.txt` 和 `.md` 文件，按目录内相对路径映射到空间文档，并保留原始扩展名。扫描结果中的 `path` 是服务端规范化后的路径，不能由浏览器凭空取得，也不会授权浏览器访问该路径。

之后可以调用 `POST /api/workspaces/:id/local-project/scan` 重新扫描，前端的“同步”按钮会触发同一协调逻辑。编辑器内容写入对应文档时，服务端会先检查文件基线哈希，再通过临时文件写入并原子替换原文件；当前不会在后台运行文件监听器。

### 浏览器导入

请求同一个绑定接口时传入 `files` 数组：

```json
{
  "files": [
    { "relativePath": "chapters/intro.md", "text": "..." }
  ]
}
```

这种方式的 `source` 为 `imported`，只把浏览器选择的文件内容导入空间数据库，不保留服务端目录路径，也不会监听原目录。浏览器目录选择不能替代服务端的实时目录绑定。

## 同步与冲突

每个映射文档保存相对路径、文件哈希、大小、修改时间和同步状态。状态包括：

- `imported`：本次扫描或导入创建了空间文档。
- `synced`：编辑器和磁盘内容一致，或编辑结果已成功写回。
- `updated`：扫描发现磁盘内容并将其载入文档，或导入内容更新了既有文档。
- `missing`：原来映射的 `.txt` 或 `.md` 文件在下一次扫描中不存在。
- `conflict`：磁盘和编辑器都在上次基线之后发生了不同修改。服务端保留两边内容，不自动覆盖文件。

发生 `conflict` 时，界面应显示冲突状态，等待用户选择保留编辑器内容或重新载入磁盘内容。当前接口只报告状态并阻止覆盖，选择动作仍需单独的产品交互设计。

`POST /api/docs/:id/local-project/sync` 在 `source: "local"` 时会写回服务端目录；`source: "imported"` 只更新空间内的导入副本，浏览器若保留 File System Access 句柄，可以另外在当前页面写回原文件。接口会返回 `{ "ok": false, "file": { "status": "conflict" } }`，调用方应读取 `file.status`，不要只根据 HTTP 状态判断写回是否成功。

当前支持 UTF-8 `.txt` 和 `.md` 文件；其他扩展名会被跳过。两种扩展名都按纯文本保存和编辑，Markdown 的标题、列表等语法不会在映射或写回时被改写；`.md` 文档在编辑器中提供源码 / 预览切换，预览不会改变原始文件内容。空间、权限、线程、建议、运行记录、文件映射和 Yjs 更新保存在 SQLite，原始文本文件仍保留在绑定目录中。

## 权限与运行边界

绑定、重新扫描和写回操作必须在空间成员的权限检查之后执行。目录路径属于服务端主机，不应从普通协作者的浏览器请求中直接暴露。多人协作时，其他客户端连接的是同一个本地服务端；他们不会直接读写主机文件系统。
